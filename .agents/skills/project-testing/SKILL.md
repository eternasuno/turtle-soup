# Project Testing

- Mirror source responsibilities under each workspace's `test` directory. Core tests own Schema contracts, selection, scoring, player-visible use cases, `session.ts` SubscriptionRef/scoped Fiber lifetimes, `settings.ts` storage use cases, Jev payloads and transport validation. Web tests own the runtime/Solid adapter, localStorage-backed SettingsStorageLive, DOM lifetimes and puzzle data; do not move core rules into the adapter.
- Use `@effect/vitest` and `it.effect` for Effect computations. Ordinary Vitest remains appropriate for Solid/DOM integration at the UI execution boundary; do not wrap every UI test only to change the test API.
- Inject official DecisionModel implementations through Layers for game/session tests, not core-module mocks. Test JevDecisionModelLayer/Live and internal DecisionClient HTTP transport with controlled HttpClient/Fetch layers. Cover configurable apiModel, requested IDs/choices, provided probabilities and missing-probabilities one-hot compatibility; the fallback is not real probability and must not change label-based scoring. Inject SettingsStorage, LocalModelResources and DecisionConfigurationTester for management tests; keep browser mocks in adapters and reset stubs. No live external calls or real credentials.
- For Effect timeouts and interruption, use TestClock, Fiber and Deferred to wait until the request has started. Assert the 30-second policy, observable fetch abort and typed failure versus interruption; do not test Effect's timer counts or internal scheduling.
- Cover fixed question labels, all/partial/no fact matches, invalid or missing answers, HTTP/network errors, timeout, caller cancellation and settings validation.
- Cover retries preserving input, PuzzleView snapshots without truth/judgmentPoints and result only after solve/reveal, duplicate submission, stale responses after reveal/reset, scoped cleanup abort and complete next-game reset in core session tests. Exercise old A success/failure while new B is pending and verify B remains loading with no old messages/errors. In web tests submit twice immediately to verify the adapter preserves the core's immediate lock; verify one ManagedRuntime is reused per configuration, replacement cancels/disposes the old runtime without resetting the session, and owner cleanup releases resources.
- Cover PuzzleDefinition judgmentPoints with nonblank id/description and per-puzzle unique point IDs (not unique descriptions). Distinguish legacy-compatible DecisionSettings drafts from provider-discriminated DecisionConfiguration with Redacted runtime API key; verify missing provider/model/backend defaults, old storage-key fallback, blank drafts and configured apiModel. Test save/test/prepare through injected interfaces, including prepare inspect→download→reinspect and complete-cache skip; do not split inspect/download/remove capabilities into arbitrary use cases. Distinguish loaded draft settings from valid request credentials; cover malformed JSON, invalid shapes, unavailable reads and failed writes. Verify core save validates and normalizes before writing through SettingsStorage, rejects invalid settings without a write, and returns normalized values only on success. Assert Option-valued domain absence/session errors, the role message union (host has no mode), and Match domain outcomes. Keep dynamic answer-key/choice, confidence bounds and fact-snapshot regression cases.
- Verify request construction once per operation, then parameterize distinct response outcomes. Remove duplicate assertions only when they cover the same contract; core and web tests using different boundaries are not automatically redundant.
- Node adapter tests resolve the client `solid-js` build via the web Vitest alias. Use createRoot and dispose its owner; do not use removed Solid 2 flush guidance. Wait for observable async completion where needed, not arbitrary timers. Assert AtomRegistry disposal, subscription cleanup, configuration runtime reuse/replacement and scoped model release. Do not confuse server no-op signals with browser behavior.
- Keep Node tests for browser-independent behavior. Add DOM/browser tooling only for actual rendered interactions; native dialog opening, Escape/close, focus, repeated-game reopening and viewport overflow need rendered verification, not source-string assertions.
- Local-model tests belong in `packages/local-model/test`: cover complete/partial/missing caches, first inspection with local lookup initially disabled, download after deletion with local lookup disabled, cache-only rejection without file fetches, model-specific deletion preserving other caches, catalog IDs/precision (Laya fp16 both, Verdict WASM q8 / WebGPU fp16 with both weights downloaded, d1 text-only q8 plus external data), and resource disposal. Cover Verdict query/passage 512-token and d1 full-prompt 16384-token boundaries: reject overflow without truncation/inference. Mock Transformers.js, Cache Storage and Workers; restore globals between tests. Cover Worker load/test/download/inference, queued cancellation, ignored active results and termination on initialization cancellation/configuration replacement/disposal.
- For model-card UI changes, verify download → use/test → save → reopen (使用中), model change with cache reinspection, model/backend matching for 使用中, isolated downloads/caches, backend change, cache-check failure/retry, deletion → download, and close during work in a browser when available. Do not claim Node mocks validate rendered interaction or real model compatibility. Preserve historical user validation of old Laya separately; it does not validate new models or the current Worker implementation. Current multi-model coverage is mocked, with no real-model/browser verification unless explicitly performed.
- Never use `--passWithNoTests`. Run `pnpm check`, `pnpm test`, `pnpm build`; report separately which checks used mocked responses and whether a real Jev call or browser interaction was verified.
